## 二、加决赛功能时的三个固定接缝（不要动别处）

### 接缝 1：跨源融合 → 新节点，不要改 `route_after_*` 的既有语义

`graph.py` 当前结构：

```
resolve → classify → (澄清则 END | retrieve) → (sql | generate) → generate
```

**加跨源多跳的推荐做法**：在 `retrieve` 与 `generate` 之间插入一个**可选**节点
（例如 `fuse`），由 `classify` 输出的 `intent == "hybrid"` 决定是否经过它。

- ✅ 允许：新增节点、新增条件边
- ❌ 不要：改 `route_after_retrieve` 现有返回值语义（`sql`/`generate` 已被评测覆盖）
- ❌ 不要：把 `retrieve` 从必经节点改成可选（会破坏「所有回答都带来源」这条基础任务要求）

### 接缝 2：新增状态字段 → `agent/state.py` + `graph.run()` 的 `initial_state` **必须同时加**

这是本项目已经踩过的坑：**`TypedDict` 加了字段但 `initial_state` 忘了加 → 运行期 KeyError**。
现成自查方式（API 不可用时也能跑）：

```python
# 比对 state.py 的字段集 与 graph.py 里 initial_state 的键集，必须完全一致
```

当前 18 个字段已对齐。**每加一个决赛字段，两处一起改。**

### 接缝 3：新增评测 → 一律独立脚本 + 独立用例 JSON，不要改已有评测的口径

已有评测的**数字是要对外报的**，改口径等于让历史结论失效。所以要加：

```
data/eval/<新项>_cases.json     # 用例与判据（含 meta 说明口径）
scripts/eval_<新项>.py          # 独立跑分，退出码 0 = 达标
data/eval/reports/<新项>-*.json # 落盘报告
```

并遵守三条已有约定（这几条是被踩出来的）：
1. **崩溃要计为全错**，不能「跳过」——跳过等于让失败不进分母，会抬高分数
2. **达标判据不能空洞**：「不下降」这类判据在「什么都没做」时也成立
   （本项目的错别字校正第一版就栽在这：改动 0 处却打印「✅ 达标」）
3. **测量真值必须与实验条件一致**（同源截断、同渲染参数），否则指标恒偏低

## 四、给后续 AI/协作者的硬提醒

1. **这个项目没有 git**，改动无法 diff 审计 —— 动手前先看文件修改时间，避免覆盖别人正在改的文件
2. **`.env` 是唯一配置入口**，不要把 key 写回源码（`config.py` 里的硬编码已清除）
3. **改向量化 / 切块 / 提示词模板这类全局参数后，必须重跑对应评测**并对比历史数字
4. **提示词里带 JSON 示例时不要用 `str.format()`** —— 花括号会被当格式化字段抛 KeyError，
   而这个异常若被宽泛 except 吞掉，会表现成「模型没发现问题」（本项目刚踩过）
