# 必读 · 数据说明：本作品使用的学生名单全部为虚构数据

> 赛题八 · 中电云计算技术有限公司　|　网信产业应用赛道
> 本说明面向评审专家，请在查看演示与评测数据前先阅读。

---

## 一、一句话结论

本作品在演示与评测中使用的《综合素质测评情况》数据集（**569 条记录、23 个字段**），
其**姓名、学号、行政班、学院、专业全部为虚构**，与任何真实学校、真实班级、真实个人无关。

**如与某位真实师生的姓名或学号雷同，纯属巧合。**
本作品不包含、也未使用任何真实院校名称与真实学生信息。

---

## 二、为什么用虚构数据

1. **能力验证需要「班级规模」的真实形态**。赛题的排序 / 聚合 / 多表关联 / 实体澄清等能力，
   要在一张有真实体量与分布的业务表上才测得出来（本作品用 569 行 × 19 个班 × 23 个字段），
   只用 3、5 行的玩具表测不出「前十是谁」「每个班平均分」「某人和某人相差多少分」这类问题。
2. **真实名单属于个人信息，不应随作品公开分发**。作品要上传公开仓库与提交包，
   因此只保留数据的**形态与数值分布**，把**身份标识整体替换为虚构值**。
3. 这样既能让评委复现全部指标，又不泄露任何个人信息——两件事同时成立。

## 四、替换方法：为什么指标仍然可比

替换采用**等长、一对一映射**，只动身份列，不动数值列：

- 聚合与排序结果只取决于数值 → **所有 SQL 查询结果不变**；
- 文本长度不变 → 文档切块边界基本不变 → **检索行为不变**；
- 实测校验：替换前后 RAG 检索命中率 `hit@1` **86.4%**、`hit@4` **95.5%** 逐位相同；
  Schema Linking `top1 20/20`、大小写一致性 `5/5` 也完全相同。
  （生成类指标会随模型单次运行有 ±1~2 例抖动，这一点已在技术文档 7.4 节如实说明。）

**映射表（原件 ↔ 虚构件）不随作品分发**，仅作者本地留存用于自审，因此无法反推任何真实信息。

  这些文件名与用例中的 `gold_doc` 字段一一对应，为保证评测可复现而保持原样。

## 七、如何自行核对

1. 打开 `data/agent.sqlite`，执行：
   ```sql
   SELECT DISTINCT 学院 FROM 综合素质测评情况;      -- 只有「示例大学信息工程学院」
   SELECT DISTINCT 行政班 FROM 综合素质测评情况;    -- 只有 2990002–2990020
   SELECT MIN(学号), MAX(学号) FROM 综合素质测评情况; -- 2025900001 / 2025900569
   ```
2. 在 `rag_data/` 与整个提交包内检索任意真实院校名称：**0 命中**；
3. `data/eval/reports/` 下的全部评测报告，都跑在这份虚构数据上，指标可按技术文档第 7 章复现。
